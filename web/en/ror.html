ROR ID application dossier

This is the real work behind an application, published before submitting it. It includes what could already be verified, what could not, and the concrete order in which each gap is closed. Obtaining a ROR ID is ROR's decision, not the applicant's.

Verdict: do not submit yet

The name is available and the seat is verifiable, but ROR's central criterion —a collective, enduring entity, recognised by name across several research sources by several people— is not met with the available evidence. Submitting today would produce an out of scope label with the reason "single-person organization". The other three gaps (own domain, normalisation of the affiliation string and unverified ISNI) are high but resolvable.

What this site demonstrates and what it does not demonstrate

A complete institutional site is not a ROR requirement and does not by itself generate eligibility. It serves four concrete purposes: it fixes a stable name, publishes the seat and contact a curator can verify, documents the governance that backs the collective character, and orders the affiliation evidence. The decision still belongs to ROR. The source of this site —including the language pipeline and the brand generator— is public and licensed at github.com/OsoPanda1/WEBINSTITUCIONAL-TAMVONLINE, so a curator can check how it was built without taking our word for it.

03 — Domain

Why the domain is a curation point

Curators tell an entity with its own identity apart from a subdomain or a page on someone else's platform. They check it against the site's copyright and the domain's registration.

Required action

The own domain already exists: visitarealdelmonte.online resolves, its mail sits with Hostinger and its A record points at the provider. What is missing is not buying it, it is stopping pointing it at a deployment that no longer exists. Concrete action, from the Hostinger panel: delete the orphan redirect and serve this institutional record from the domain, with the WHOIS registration in the entity's name and the name published in the domains field. While the domain returns a 404, domains deliberately stays empty: citing ROR an address that does not open is worse evidence than citing none, because the curator is going to open it. An address on *.vercel.app or *.odoo.com does not certify independence, and a ROR ID lives for decades: it should not end up linked to a hosting URL that can change. Choosing a network-specific name later (tamvonline.network, tamv.org.mx) is an additional step, not the blocker.

04 — Collective evidence

The criterion that decides the application

ROR looks for the organisation to be recognised by name in several reputable sources and by several people. This is what the public record shows today.

What does exist

  • A stable name used since 2026 in deposits with a DOI.
  • A matching seat in two independent sources (ORCID and the documentary canon).
  • Real production under a CC BY 4.0 licence, not only descriptive pages.
  • A written governance framework, with published admission criteria.
  • An affiliation string retrievable in OpenAlex as raw text.

What is missing

  • Plurality of people: the 23 Zenodo records, the 18 DataCite DOIs, Figshare, OSF and the CITATION.cff files reviewed name a single person.
  • Empty Zenodo community: the community tamvonline-oficial lists no members.
  • External peer review: none of the production consulted shows identifiable external review.
  • Disambiguation: OpenAlex mis-assigned two records to "RDM Group (UK)".
  • Cross-citation: no external, self-managed source outside our own uses the name.

The line that is not crossed

Creating fake profiles, inventing collaborators, asking third parties to sign without having contributed, or inflating metadata to meet the plurality criterion would be documentary fraud. The VETRA canon itself blocks a proposal for falsified authorship or material concealment of conflicts, and ROR withdraws records when it discovers fabricated metadata. Collective evidence is only valid if it is genuinely collective.

05 — Draft

Record in the ROR v2.1 schema

There is no need to send JSON: the form and the issue template are textual. Even so, delivering metadata in the shape of the current schema speeds up curation and exposes inconsistencies.

{
  "names": [
    { "value": "TAMV Online Network", "types": ["ror_display"], "lang": "en" },
    { "value": "TAMV",                 "types": ["acronym"] }
  ],
  "types":    ["other"],
  "status":   "active",
  "established": 2020,

  // Sin "relationships": en v2.1 la independencia se expresa con el arreglo vacío.
  // El vocabulario v1 ("independent", "branch") ya no aplica.
  "relationships": [],

  "links": [
    { "type": "website", "value": "https://DOMINIO-PROPIO-PENDIENTE/" }
  ],
  "domains": [],  // vacío hasta registrar el dominio propio y su WHOIS

  // external_ids: ninguno organizacional. No se solicita ISNI ni Wikidata
  // para obtener un ROR ID; se añaden cuando un curador los encuentra.
  "external_ids": [],

  "locations": [
    {
      "geonames_id": 3523180,
      "geonames_details": {
        "name": "Mineral del Monte",
        "continent_code": "NA",
        "continent_name": "North America",
        "country_code": "MX",
        "country_name": "Mexico",
        "country_subdivision_code": "HID",
        "country_subdivision_name": "Hidalgo"
      }
    }
  ]
}

The required fields of a v2.1 record are admin, id, locations, names, status and types; admin and id are generated by the system, and ROR derives lat/lng from the GeoNames. Exactly one name must carry ror_display, and the types allowed for names are acronym, alias, label and ror_display.

06 — Route

How it is submitted, when it is ready

Two official channels. ROR documents that the curation queue determines the timings, and that not all applications are approved.

Main channel

Curation form

curation-request.ror.org — open to anyone, without an account or affiliation, and it returns a tracking link.

Before filling it in: search the name at ror.org/search. ROR documents that hundreds of applications request something that already exists.

Alternative channel

Issue in ror-updates

The "Add organization to ROR" template in ror-community/ror-updates. Title with the prefix Add a new organization to ROR: .

Initial labels new record and triage needed. Priority 1 is for new records; approved ones receive a version milestone.

Checklist before submitting
  • Own domain registered, resolving, with WHOIS in the entity's name.
  • Founder's employment in ORCID reinstated as a current position, with no end date.
  • The TAMV Online Network string normalised in the current deposits and in the CITATION.cff files.
  • ISNI verified or removed from all pages.
  • At least three distinct people with TAMV affiliation visible in citable productions.
  • An English page of the institutional record accessible to the curator.
  • Prior search in ROR documented with a date.
07 — Sequence

Remediation plan

Ordered by dependency: phases 1 and 2 require no one else; phase 3 is the one that decides eligibility.

Phase 1 · Immediate

Stop contradicting itself

Register an own domain · correct the closed employment in ORCID · normalise the affiliation string · remove or verify the ISNI · publish this bilingual record.

No significant external cost. It does not improve eligibility by itself, but it removes the contradictions a curator finds in five minutes.

Phase 2 · 1–3 months

Make the network observable

Public directory of members with consent · deposits with real contributors · a Wikidata entry as a corporate entity · correction notices to the old records.

Goal: that the name exists in sources not controlled by a single person.

Phase 3 · Collective evidence

Have other people sign

Verifiable co-authorships and acknowledgements among members and external collaborators · federated projects with already-registered entities · identifiable external review.

This is ROR's condition. If it is not met, phases 1 and 2 do not change the outcome.

A second route, faster and useful today

The immediate goal need not be a ROR ID. Identifying each member with their ORCID and linking their DOIs solves the real problem —the visibility and attribution of researchers without an institution— without waiting for a curation decision. The ROR ID adds organisational affiliation on top of that base, and is requested once that base exists.
